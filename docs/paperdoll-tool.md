# 紙娃娃編輯器（tools/paperdoll）

用來調整紙娃娃零件圖（身體、頭、裝備、武器）的大小與位置，讓它們疊在一起對得上。

開啟：`npm run dev` 後瀏覽 `http://localhost:8080/tools/` 的「紙娃娃」分頁（殼見 [tools-shell.md](tools-shell.md)；只支援 Chrome／Edge，用 File System Access API 讀寫檔案）。正式 build 只打包 `index.html`，工具不會進遊戲。

## 設計原則

- **像素操作永遠從原圖算**：每層保留原圖 `src` 和步驟清單 `ops`，畫面是「原圖依序重播 ops」的結果，存檔時才把結果烘進 PNG。步驟有九種：`xform`（取輸入的小數範圍縮放成 w×h，「保留框內」裁切／縮放／trim 都是它）、`erase`（把 x,y,w,h 挖成透明，「移除框內」裁切，尺寸與 `x`／`y` 不變）、`mask`（多邊形 `pts:[[x,y]…]`，`keep` 時只留多邊形內、否則挖掉多邊形內；反鋸齒、nonzero 填色，尺寸不變）、`alpha`（清除 alpha < t）、`fill`（alpha ≥ t 的像素整組換成 r,g,b,a）、`key`（RGB 完全等於 r,g,b 的像素變透明，不看 alpha）、`removeGreen`（綠底去背：`G > 100` 且比 R、B 都大 `rgbThr`，或不透明像素的 HSV 落在範圍內，就變透明；「移除綠色」模式）、`warp`（網格變形）、`paint`（像素修補 `px:[[x,y,r,g,b,a]…]`，那格直接換成這組 RGBA）。相鄰的 `xform` 會合成一個（`compose()`），相鄰的 `alpha` 取較大的 t（`fill`／`key` 不合併，顏色不同就是不同步驟），所以「縮放 → trim → 再縮放」只會從原圖取樣一次；只有中間夾著其他種步驟時才會分成兩段。
- **網格變形（多框）**：一步 `warp` 記一組框 `frames:[{x,y,w,h,cols,rows,pts}]`，矩形是變形前那張圖的整數座標（限制在圖內），`pts` 是每個格點變形後的位置（同一套座標，可超出原圖）。`warpFrames()` 依序處理每個框：從目前結果取出框內、挖掉、貼上框內變形後的圖（重疊的框吃前一個框的結果）；輸出畫布涵蓋原圖和所有 `pts`，(0,0) 對應 `warpFramesBounds()` 的 `bx,by`。框內變形用 `warp()`：每格拆兩個三角形，逐像素以仿射反查、預乘 alpha 雙線性取樣。舊格式（整張圖一張網格 `{cols,rows,pts}`、沒有 `frames`）照樣重播，接著編輯時轉成一個整張圖的框。
  - 操作：拖曳空白處拉出新框（格數取面板，預設 4×4），點框切換目前的框（重疊時往下輪），拖框外的小方塊調大小（點等比例跟著、已做的變形保留），Delete／Backspace 刪目前的框。目前的框白框＋青網格＋控制點，其他框灰色、不顯示點。控制點：拖曳移動選取的點；Shift+拖曳框選加選、Ctrl+拖曳框選取消，Shift／Ctrl+點單點加選／取消；拖點時按著 Shift 只沿水平或垂直（螢幕方向，圖層有旋轉時換回圖片座標）；方向鍵微調。框開始拖點之後要先「重設」才能改格數。
  - 套用：「確定」（Enter）把框寫成一步 `warp`（沒變形也沒步驟的框不寫）。
  - undo：每個框有自己的步驟 `hist`（改之前的樣子，最多 50 步）和 `fut`（redo）。`warpRecord` 記目前這框：拖點／把手（一次拖曳一步）、方向鍵、重設格數。`hist` 跟著框寫進 op（`frames[i].hist`），所以確定後再進來、存專案再開都還能退；`fut` 不存。變形模式裡 Ctrl+Z／Ctrl+Y 只動目前的框：退到剛拉出來的樣子（沒變形）再按就拿掉這個框、換上一個框；一個框都沒有時依序救回 Delete 掉的框（`deleted`，只在這次模式裡）；再沒有就停住，不走全域 undo（要退更早的操作先離開模式）。拿掉／救回框的 redo 記在 `frameRedo`，Ctrl+Y 先 redo 目前這框，再處理它。離開模式時整段只記一筆全域 undo。切換圖層／模式時有沒套用的修改會 `confirm` 問要不要套用（取消＝放棄），關分頁也會擋；Esc／取消鈕直接放棄。
  - 最後一步是 `warp` 時再按「變形」會拿掉它、重播出變形前的圖並接著編輯同一組框（變形前的 `x`/`y` 由 `bx,by` 反推），所以不會累積取樣；但之後又 trim／裁切過，後面多了 `xform`，再變形就是新的一步 `warp`。編輯中的預覽就是最後結果（直接改圖層的 canvas／x／y），取消時用快照還原。
- **undo**：Ctrl+Z／Ctrl+Y，快照只存 `ops`、`canvas` 的參照和擺放數字；兩者都不會被就地修改（每次操作換新的），所以快照不用複製像素。合併用「結構快照」（`snapList`：`S.layers` 複本＋`S.active`），被合併的圖層物件原封不動、也不 `forget`，換回清單就還原；刪除圖層時會把它從結構快照裡拿掉（不然 undo 合併會讓它復活）。刪除、拖曳排序本身仍不能 undo。
- **合併圖層**：「向下合併」（Ctrl+E，選取層＋正下方那層）、「合併可見」（Ctrl+Shift+E，顯示中且沒鎖定的全部）。用 `flatten()` 壓成一張新圖層，放在最底層的位置、名字 `底層名-merged`、沿用底層的 `dir`/`path`；旋轉烘進像素（`a=0`），中心點的世界座標沿用最底層的（`x`/`y` 不變、重算 `ox`/`oy`）。有半透明圖層時用 `confirm` 問要不要烘入不透明度（取消＝照 100% 合）。向下合併遇到隱藏／鎖定的圖層會拒絕。新圖層沒有原圖路徑，跟拖進來的圖一樣要先存檔才能存專案。
- **複製圖層**：「複製」（Ctrl+J）把選取層淺拷貝一份（`ops`／`canvas`／`src` 共用參照，反正不會就地修改），放在它正上方、名字 `原名-copy`、原圖路徑相同；用結構快照所以能 undo。
- **裁切四種模式**：保留框內（`xform`）、移除框內（`erase`）、移到新圖層、複製到新圖層。後兩者先複製一層（同上，但名字沿用原名）再對副本做 `xform`，所以副本也是從原圖只取樣一次、內容不跳位；「移到」另外在原圖層加 `erase`。這一步同時改圖層清單和原圖層像素，用群組快照（`{group: [snapList, snap]}`），一次 undo 全部還原。
- **多邊形裁切**：裁切面板選「多邊形」後，四種模式照樣用（`cropSel()` 依形狀回傳 `keep`／`cut`）：保留＝`mask(keep)`＋裁到外接矩形的 `xform`（往外取整、限制在圖內，頂點可以點在圖外）；移除＝`mask(挖掉)`。單擊加點、點第一點或雙擊閉合、Backspace 倒退（已閉合就先解開）、Shift 讓這一邊鎖 45°；閉合後拖頂點、點邊插點（同一下直接拖），點空白不做事；Esc 先清掉選取（矩形也是），再按一次才離開模式。頂點存圖層本地座標，容錯 8 螢幕 px。反鋸齒的邊在「移到新圖層」疊回去時 alpha 會略低一點（一般 over 合成不是相加），縮小後看不出來。
- **顏色模式**：「填色」「去色」共用一個色票，即時預覽、確定才寫入步驟。點畫布是滴管，吸選取圖層（目前步驟的結果）的 RGB 填進色票；填色的 alpha 欄不跟著吸，免得吸到半透明邊緣把它改掉。去色是完全相等，所以背景色要用滴管吸，不要用色票挑。
- **自動模式**：把一張 AI 產的綠底整套圖（左上是戴著頭盔的頭、頭盔右上、護甲左下、靴子右下）拆成零件，左上沒有零件認領、整塊丟掉。面板三行（零件／象限／scale%／x／y，x/y 是遊戲單位），改了寫進 `localStorage`（`paperdoll.auto`）並跟著專案設定 `settings.auto` 存讀，「還原預設」回到程式裡的 `AUTO_DEF`。進模式時什麼都不動（只是讓你先調數字），按「確定」才 `autoSplit()`：把每個零件複製一層，步驟依序加 `alpha`（t=32）→ `removeGreen`（同模式預設值）→ `blobs`（只留自己的塊）→ `xform`（裁到零件範圍）→ `xform`（縮小，op 上多記 `pct`）；裁切跟縮小分兩步，前後片的 mask 才能插在中間。零件會跨過中線（護甲肩膀），所以不切象限：去綠後照門檻把不透明像素分 8 方向連通塊（`PX.blobs()`），比最大塊 1% 還小的當雜點丟掉，其餘依重心落在哪個象限歸給該零件（兩隻靴子是兩塊），零件範圍＝它所有塊的外接矩形。範圍會跟別的塊重疊（左上頭的下巴伸進護甲範圍），所以裁切前先加 `blobs = {t, pts}`（`PX.keepBlobs()`）：`pts` 是這個零件每塊的種子像素（`PX.blobs()` 回傳的 `sx/sy`），重播時從種子做同規則的連通，沒連到的清成透明。左上戴著的頭盔常細細黏著護甲、合成一塊後重心落在左上（護甲整個被丟掉），所以四個象限湊不齊時逐步加侵蝕量重分（1～`AUTO_ERODE`=12 px，取第一個四象限都有塊的）：先依棋盤距離侵蝕，核心各自分塊再一圈圈同時長回原本的像素（先到先得），整塊被侵蝕光的照原本連通；用到的侵蝕量記在 `blobs.erode`，`keepBlobs()` 照同樣分法重播；中心點 `0.5,1`、`a=0`；疊在原圖正上方（由下往上 靴子、護甲、頭盔），原圖隱藏、選取頭盔；頭盔拆了前後片的話，隱藏的原頭盔層放在前片正上方；有標記成頭（♂頭／♀頭）的參考人偶時 `autoStack()` 再照遊戲深度（`PART_DEPTH`）搬：頭盔（前片）放在最高的頭／髮標記層上面，後片、護甲、靴子由上往下接在最低的頭標記層下面（沒有頭標記就不搬，後片照前後片模式丟最底層）。護具零件在圖層列名字前面有藍灰色標示（`armorBadge()`，看 `auto.key` 算、只顯示不存）：盔／甲／靴，頭盔的前後片（本身沒有 `auto`，從原頭盔層找）標盔前／盔後。沒有塊歸給它的零件略過，一個零件都沒有就只顯示訊息、什麼都不建。拆完記一筆群組 undo（原圖的顯示也記進快照：`hist.snap(L, true)`），**留在模式裡**、「確定」反灰。
  - **一張圖只拆一次**：零件記 `auto = {key, gid}`、原圖記 `autoSrc = gid`，兩個欄位都跟著專案存讀（`cloneAbove()` 複製出來的圖層不帶）。選原圖或任一零件按「自動」，只要畫布上還有這組零件就直接進「調整」（`autoEnter()`）；零件刪光（或 undo 掉）才能再拆，再拆沿用原圖的 `gid`。
  - **調整**：面板顯示這組零件的實際值（scale% 讀 `xform.pct`、x/y 從圖層位置換算），沒有零件的那行反灰。去綠圖（`mode.T`）從第一個零件自己的步驟反推（`xform` 之前那段，第一次改 scale 才 replay），所以原圖被刪了也能調；各零件的裁切框取自它的 `xform`。改數字時 `autoApply()`：scale% 有變才從 `T.canvas` 重做裁切＋縮小（ops 換成 `[...T.ops, 裁切, 縮小]`，拆了前後片的話 `splitSync()` 跟著重播前後片），x/y 只改位置，整行同時寫回全域預設。有 `paint` 的零件改 scale% 會 `confirm` 問要不要清除修補，否＝數字退回。
  - **拖曳／方向鍵**（拆完後才有；還沒拆時點畫布不做事）：等於用滑鼠輸入 x/y（`autoMove()`），步進 1 世界 px、Shift 鎖水平／垂直；拖的時候面板跟著跳，放開時寫回全域預設。點選只看這組零件（`pick(w, only)`，會穿過疊在上面的別的圖層，跳過鎖定／隱藏的），點到的變選取、不離開模式，點空白不做事。方向鍵微調選取的零件（1 px，Shift 10 px），每按一次就寫回預設。
  - **擋下再調**：零件步驟要是 `[...去綠, blobs, xform(裁切), xform(有 pct), ...paint]`（`autoBase()`；沒有 `blobs` 的舊零件也認，`autoKeep()` 取出 `blobs` 跟著重播）。拆完後再裁切／trim／縮放，新的 `xform` 會跟它合成一步（`PX.compose()` 不帶 `pct`），或後面多了別的步驟，就不能再進自動，要重拆先取消自動。只拖位置不算改過。舊專案的零件（裁切縮放同一步）也一樣擋下。
  - **按鈕**：「取消」（`autoRevoke()`）＝撤掉這次自動：刪掉整組零件、原圖重新顯示並選取（原圖不在就只刪零件），記一筆 undo；還沒拆時就只是離開。「離開」／Esc（`cancelMode()`）＝保留結果離開。調整中點原圖或這組零件不離開模式，點別的圖層＝離開；刪部分零件就從 `mode.parts` 拿掉（模式內步驟和 `mode.snap` 也用 `History.drop()` 拿掉它，免得 undo 讓它復活），刪光就離開。
  - **存到 item…**（`saveItems()`，拆完、有專案資料夾才能按）：對話框頭盔／護甲／靴子三列（這組沒有的零件那列反灰），每列勾「處理」、下拉選同 cat（`CAT_HELMET`／`CAT_CHESTPLATE`／`CAT_BOOTS`）的 item 或「＋新增」，預設選 `equip.sprite`＝圖層名的那件、配不到就新增。三個勾（預設都勾）：`更新圖`（寫 PNG＋換 sprite）、`更新設定`（scale/x/y/a/ox/oy 一組，寫法同 `writeEquip()`，`drop.scale` 跟著設成 `equip.scale`）、`更新ICON`（`icon` 設成檔名，原本空的也補上），三個都不勾＝不處理。
    - 手動選了 `<部位>-<系>-<階>` 的 id（如 `helmet-hvy-1`）：還沒手動選過、有零件的其他列自動帶到同系同階（`armor-hvy-1`、`boots-hvy-1`，cat 要對），找不到就不動；選回「＋新增」、舊命名 id 不帶。
    - 已存在的 item：檔名帶它的 `equip.sprite`；`更新圖` 沒勾時檔名鎖住。改了檔名＝換圖：新 PNG 寫進 `equips/`（舊圖不刪），`equip.sprite` 換新名，列上提示「sprite：舊 → 新」。勾 `更新圖` 時 `drop.sprite` 一律設成檔名（完整原圖，拆了前後片也不用 -front）。沒有 `drop` 就補 `{sprite: equip.sprite 去掉 -front}`，其他 key 保留（`dropOf()`）。
    - 新增：id 預設下一個流水號（`helmet_NN`／`chest_NN`／`boots_NN`）、lab 必填，三個勾強制勾；寫 `{cat, icon: 檔名, lab, equip: {sprite, scale, x, y…}, drop: {sprite: 檔名, scale}}`，頭盔多 `hideHair: true`，插在同 cat 最後一件後面；gold/def/des 去道具編輯器補。
    - 零件拆了前後片：勾 `更新圖` 時一起寫 `<檔名>-front.png`、`<檔名>-back.png`，`equip.sprite` 指前片、`equip.back` 指後片、`icon` 是完整的 `<檔名>`（`setSplit()`）；配 item 時 `equip.sprite` 是 `<檔名>` 或 `<檔名>-front` 都算；前後片缺一張、三層尺寸位置對不上、`-front`／`-back` 撞到 `equips/` 以外的圖都標紅擋存。
    - 檢查（`itemCheck()`，`texKeys()` 直接掃 `textures/`，不讀可能還沒更新的 textures.json）：id 撞到、lab／檔名空的、兩列同一件或同檔名、檔名撞到 `equips/` 以外的 texture → 標紅擋存；覆蓋 `equips/` 裡「不是這件原本 sprite」的圖 → 列上提示，存檔時一次 confirm；覆蓋自己的圖但別件也共用 → 只提示。存檔時重讀 item.json、重掃再檢查一次，整份重寫一次並廣播。圖層名不改；零件半透明時多一個「烘入不透明度」勾。
  - **載入 item**（`loadItems()`，在「存到 item…」旁邊，啟用條件一樣，不跳對話框）：每個零件照 `itemMatch()` 找 item（`equip.sprite` 是圖層名或 `<圖層名>-front`，武器多認 id＝圖層名），對到就把擺放套上去：x/y，武器多 a/ox/oy（item 沒寫的 key 當預設 0／0.5／1，`writeEquip()` 會刪掉預設值）。scale% 不動（item 只有 `equip.scale`＝全域 `S.scale`，縮小比例已經烘進 PNG，反推會有誤差）。走 `autoApply()`，所以前後片跟著搬、整行寫回全域預設（目前部位／武器分類）；整次一步模式內 undo，一個都沒對到或數字都沒變就不記。對不到的零件不動；狀態列列出「零件 ← id」、找不到的零件，`equip.scale` ≠ `S.scale` 時照套並警告（x/y 用 `S.scale` 換算）。每次按都重讀 item.json。
  - **undo**：模式內有自己的步驟（`mode.hist`／`mode.fut`，最多 50 步，`autoStep()` 記這組零件改之前的樣子），改一個數字、拖一次（真的動到才算）、按一下方向鍵各一步；Ctrl+Z／Ctrl+Y 一步一步退／重做，並把零件現在的數字寫回全域預設，退到底停住、不走全域 undo（剛拆完按也不會退掉拆）。離開模式時還有步驟才記一筆全域 undo（進調整時的快照 `mode.snap`），拆本身是另一筆，所以離開後先退調整、再退拆；「取消」前有步驟也先記這筆。
- **像素模式**：修縮小後成品的細節（雜點、殘綠、斷線），不是拿來從零畫圖。鉛筆（B）／橡皮擦（E）、方形筆刷 1～8px（`[`／`]`），鉛筆是**取代**成色票的 RGBA（不混色）、橡皮擦是 alpha 0，畫到圖外的直接裁掉；色票跟顏色模式共用（`pxRgb`↔`colRgb` 同步，alpha 是自己的 `pxA`），Alt+點吸 RGB 連 alpha（跟顏色模式不同：修補要的是一模一樣的像素，顏色模式的填色 alpha 則不跟著吸）。筆畫畫在模式的 `preview` 上（每筆只 `putImageData` 筆刷範圍），`map`（`y*W+x → rgba`）是要寫進步驟的內容；確定（Enter）寫成**一步** `paint`、全域 undo 一筆，座標是前面所有步驟跑完那張圖的像素座標；最後一步就是 `paint` 時再進模式會拿掉它、筆畫併進同一步。模式內 Ctrl+Z／Ctrl+Y 一筆一筆退（按下到放開＝一筆，真的畫到圖上才算，最多 50 筆），退到底停住，不走全域 undo；切換圖層／模式時有沒套用的筆畫 `confirm` 問要不要套用，關分頁也會擋。一格像素 ≥ 8 螢幕 px 才畫像素格線，游標畫出對齊格子的筆刷框（鉛筆用色票色、橡皮擦白色）。選取圖層鎖定或隱藏時不能進模式。
  - **護具／武器／頭像**：面板最上面 radio `護具｜武器｜頭像`（`S.auto.kind`，`'armor'`／`'weapon'`／`'head'`，跟著 `paperdoll.auto`／專案設定存讀）；還沒拆時切換就照新種類重算（`autoEnter()` 重進），拆完反灰；選已拆的零件再進來照零件的 `auto.key` 決定種類並寫回 `kind`。「還原預設」不動 `kind`。
    - **武器**（`kind: 'weapon'`）：透明底、直立的單把武器，只有一個零件，名字跟原圖名一樣（不加 `-weapon`，護具才加 `-<部位>`；`auto.key = 'weapon'`）。步驟 `alpha`（t=32）→ `blobs`（比最大塊 1% 小的當雜點，其餘全收）→ `xform`（裁切）→ `xform`（`pct`），**不去綠、不拆前後片**（`autoBase()` 對武器零件認 `alpha` 而不是 `removeGreen`）。面板一行 `scale%｜x｜y｜a｜ox｜oy`（`AUTO_F.weapon`），預設 `AUTO_DEF.weapon` = `10｜-13｜18｜0｜0.5｜0.85`，改了寫回全域預設。
    - **分類**：武器的 6 個數字照分類各存一組（`S.auto.weapon[cls]`，`WCLS` 寫死：`sword｜axe｜hammer｜dagger｜staff｜bow｜default`，內建預設＝`AUTO_DEF.weapon` 蓋上 `WCLS` 第三欄（`wclsDef()`，`default` 不蓋）），`S.auto.cls` 是目前分類，`autoCfg()`／`autoWith()` 讀寫目前那組（護具照舊 `S.auto[key]`）。分類從名字第一個 `-`／`_` 前面猜（`wclsOf()`，`sword-iron`→`sword`，清單外歸 `default`），武器那列旁邊的下拉（`#auCls`）可改：沒拆只換顯示的數字；拆過就把那組套到零件上、記一步模式內 undo（undo 連分類一起退）。拆出的零件記 `auto.cls`（跟著 sidecar／專案存），再進來用它不重猜。拖曳、方向鍵、改數字都寫回目前分類；「還原預設」武器只還原目前分類、護具只還原護具。舊格式（`weapon` 直接放數字）讀進來複製到每個分類（`wclsFrom()`）。`-icon` 的 `ICON_AUTO` 不分類。
    - x/y＝手的位置，畫布上橘色十字標支點（`C.x, C.y`）：在十字 8 螢幕 px 內拖＝改 ox/oy、x/y 不動、圖跟著游標走（世界位移轉成圖層本地位移，`autoPose()`）；按住 R 拖＝轉 a（Shift 鎖 15°）；其他地方拖＝改 x/y。一次拖曳一步模式內 undo。
    - a＝待機（拿著）時的角度：存到 item 跟護具一樣寫 `equip.a`（0 不寫、存到 0.1 度）；anim.json 的影格是絕對角度，播完轉回 `a`（`pose.js` 的 rest）。`-icon` 不管 `a`，固定斜 45°。
    - 存到 item：只有一列，下拉列 `CAT_WEAPON`；預設選 `equip.sprite`＝圖層名的那件，配不到再看 **id＝圖層名**（新武器還沒有 `equip`）；PNG 寫 `textures/weapons/`（`itemDir()`，撞名檢查也以 `weapons/` 為「自己家」）；`更新ICON` 另外產一張斜擺的 `weapons/<檔名>-icon.png`（`iconOf()`，固定 `ICON_AUTO` = 100×100｜45°｜90%，不看 icon 模式的設定；來源是縮小前的圖，有勾烘入就乘不透明度）並設 `icon: "<檔名>-icon"`（`iconKey()`），可以只勾它重產 icon，`-icon` 撞到 `weapons/` 以外的圖就標紅擋存，`drop.sprite` 照舊是 `<檔名>`；新增的 id 沒有流水號、要自己填，只寫 `cat/icon/lab/equip/drop`，其他去道具編輯器補。
    - **批次存武器**（`saveBatch()`）：檔案樹 Shift／Ctrl 多選 PNG，右鍵「批次存武器到 item…」（點在已選的列上＝整批，點在沒選的列上＝只有那一張；照路徑排序）。**不建圖層**，同名 sidecar 不管，每張原圖照上面武器的步驟算（`batchPart()` 做一個假圖層給 `autoPlan()`／`autoScale()`／`autoPlace()`，欄位跟自動零件一樣，所以 `itemCheck()`／`iconSrc()`／`writeEquip()` 都直接用），不逐把調。對話框（`batchDialog()`）頂端一行 `分類｜scale%｜x｜y｜a｜ox｜oy`＝那個分類的全域預設（`S.auto.weapon[分類]`，分類預設第一列（有武器的）的分類，切了換數字；改了寫回、跟自動面板同步，只重算同分類的列，scale% 變了才重算成品）、一組 `更新圖｜更新ICON` 套用整批、`更新設定` 是每列勾勾的全選（全勾＝勾、全不勾＝不勾、有勾有不勾＝半勾 indeterminate，點了全部跟著它；沒有對到 item 的列就反灰）；每列：成品縮圖（實際像素，太大才縮）、`-icon` 縮圖（沒勾更新ICON 反灰）、分類下拉（照檔名猜，改了用新分類的數字重算那列）、下拉 `不處理｜＋新增（填 id／lab，三項強制做）｜CAT_WEAPON 的 item`（配法同單張 `itemMatch()`，配不到預設不處理）、對到 item 才出現的「更新設定」（預設勾、換 item 不重設；沒勾不寫 scale/x/y/a/ox/oy，＋新增一定寫），檔名固定是原圖名（沒勾更新圖時是原本的 sprite 名，只重產 `-icon`）。清除透明後找不到武器的列反灰不能選。存檔走跟單張共用的 `commitItems()`，差別是換 sprite、共用圖（warn）也跟覆蓋一起在存前 confirm 一次。
  - **頭像**（`kind: 'head'`）：透明底，左邊光頭（含鬍子）、右邊頭髮（臉的位置是綠色的洞）。步驟同護具 `alpha` → `removeGreen` → `blobs` → `xform`（裁切）→ `xform`（`pct`），去綠後照重心在原圖中線左／右分成頭／頭髮（`side`），只有一邊有塊就全部當頭、沒有頭髮零件（狀態列提示、頭髮那行反灰）。零件 `<原圖名>-head`／`<原圖名>-hair`，頭髮先建所以疊在頭上面；不拆前後片、不批次。
    - 面板（`#auHead`）：頭、頭髮各自 scale%，頭髮那格後面是 🔗 連動勾（`#au-link`，`S.auto.headLink`，跟著 `paperdoll.auto`／專案設定存讀，舊設定沒有＝開，「還原預設」也還原成開）。連動時頭髮 scale% 反灰、改頭那格頭髮設成一樣的值（兩個一起套、一步 undo，`autoApplyAll()`）；不連動各改各的。打開連動時數字不一樣就馬上把頭髮對齊頭（拆過記一步模式內 undo，`autoState()` 記 `link`，undo 連開關一起退；頭髮有修補不清除就不打開），關掉不改圖不記步驟；沒有頭髮零件時勾勾跟著反灰。存到 role 的 `scale` 照樣是 `S.scale`（縮小比例烘進 PNG）。頭、頭髮各自 x/y（遊戲單位，`AUTO_DEF` 預設照 wick 的 `head`／`hair`）。不畫參考身體：頭髮對頭在這裡拖，頭對身體的細調去試穿分頁。「還原預設」只還原頭像（連 W/H/%）。
    - 頭像（`portraitOf()`）：頭、頭髮縮小前的圖（`iconSrc()`，照 `C.ops` 快取在 `preCache`）照目前擺放疊起來：以兩個裡最大的 pct 為基準（那個用縮小前的圖、其他照 `pct/最大 pct` 縮小，x/y 乘 `100/最大 pct`），pct 不同時大小、位置才跟畫面上一致，再交給 `iconOf()` 角度 0、等比塞進 尺寸×尺寸 的 %、置中（% 可以超過 100，超出框的裁掉）。尺寸／% 是全域預設 `S.auto.portrait`（`AUTO_PORTRAIT` = `{size:100, fill:100}`，% 上限 400；舊的 `{w,h,fill}` 由 `ptFrom()` 轉成 `size=w`、fill 重設 100），面板下面即時預覽（拆完才有）。
    - **存到 role…**（`saveRole()`／`roleDialog()`／`commitRole()`，按鈕跟「存到 item…」同一顆，頭像時換字）：下拉列出 role.json **所有角色**（不新增角色），用 `<optgroup>` 依 `kind` 分組（順序、組名借 `tools/role/schema.js` 的 `KINDS`／`KIND_NAMES`，沒有或不認得的 kind 歸「其他」），每項 `id 名字（head.sprite／沒有 head）`；`body.sprite` 有值但不是 `body-` 開頭（整張圖、sheet 格子，`roleBodyOdd()`）前面加 ⚠，選了在上方顯示黃色警告「存了會疊兩顆頭」，不擋存檔、不改 body。預設角色（`roleMatch()`）先看零件的 `auto.role`（存成功後寫進這組頭／頭髮零件，跟著工作檔 sidecar 存讀，不進 undo），再來 id＝原圖名，再看 `head.sprite`＝`head-<原圖名>`（`headBase()` 從零件名去掉 `-head`／`-hair`），都沒有就要自己選。三列 頭／頭髮／頭像，檔名預設 `head-<id>`／`hair-<id>`／`portrait-<id>`（不照舊 sprite，好幾個 NPC 共用 `head-trump`），換角色就重設；頭、頭髮勾 `更新圖`（PNG＋`sprite`）／`更新設定`（`scale`＝`S.scale`、`x`、`y`），頭像勾 `更新頭像`（PNG＋`icon`）。角色沒有 `head`／`hair` 就一定要更新圖（新建那個物件）。PNG 寫 `textures/roles/parts`、頭像寫 `textures/roles/portraits`（`ROLE_DIR`）。
    - 檢查（`roleCheck()`）：沒選角色、檔名空的／不合法、列之間同檔名、撞到自己資料夾以外的 texture → 擋存；檔名跟舊的不同 → 提示「sprite：舊 → 新」（頭像是 icon）；覆蓋自己資料夾裡已有的圖（換了檔名，或檔名沒變但別的角色也用這張）→ 提示，存檔時一次 confirm。存檔時重讀 role.json、重掃再檢查一次，整份重寫並廣播。
    - **載入 role**（`loadRole()`）：同樣用 `roleMatch()` 找角色，把 `head`／`hair` 的 x/y 套回零件（scale% 不動，`scale` ≠ `S.scale` 時照套並警告），角色沒有 `hair` 就只套頭；整次一步模式內 undo（跟載入 item 共用 `autoApplyAll()`）。
  - **有 `paint` 的圖層不能再縮放、變形、自動拆**（`setMode`／`autoEnter` 擋下並 alert；自動拆出的零件有 `paint` 可以再進自動調，見上）：`paint` 記的是某個尺寸下的格子，換尺寸就對不上，而且縮放的 `xform` 會被 `paint` 隔開、合不回前面的 `xform`，修過的像素會被重新取樣。純裁切（保留框內、trim、移到／複製到新圖層）跟其他不重取樣的步驟照順序疊在後面就好。要再縮放就按「清除修補」：拿掉這層所有 `paint`、重播、記一筆全域 undo，模式內還沒確定的筆畫一起丟掉。
- **前後片模式**：把頭盔拆成三層：原圖 `X`（隱藏、步驟不動，記 `splitSrc = gid`，跟著專案存讀）、蓋住頭的前片 `X-front`、被頭蓋住的後片 `X-back`（前片疊在原圖正上方，後片新建時放到整個圖層清單最底層，已經有的後片不搬），遊戲用 `equip.sprite`＝前片、`equip.back`＝後片畫在頭後面、`icon`＝完整的原圖（見下方「跟遊戲的對應」）。
  - **存成 × 切割**：「存成」（radio `spHow`，切線的 `cut`）決定多邊形那塊怎麼存，「切割」（radio `spMethod`，放在共用的 `#spCtl`，切線的 `method`）決定多邊形怎麼產生，兩者獨立、四種組合都行，多邊形的意義都是「從前片拿掉的那塊」。切割：**沿線**（`'trace'`，`PX.splitTrace()`，見下面「追線」）、**魔術棒**（`'wand'`，`PX.splitCut()`，見下面「魔術棒」）。**單向連動**（`spPreset()`）：切換存成時帶切法——前後片＝沿線，挖除＝魔術棒＋☑ 下＋☐ 右（數字不動）；之後手動改切法不動存成；再進已拆的組照 mask 帶回、不套連動；自動面板的 `不拆／前後片／挖除` 同一套（`autoSpNew()`／`autoSpSync()`）。`S.sp.method` 記在 localStorage（舊設定沒有就挖除＝魔術棒、否則沿線）。
  - **前後片／挖除**：前後片＝多邊形那塊變 `-back`、其他留 `-front`；挖除＝把前片那塊挖成透明、不做後片，一組只有原圖 `X`＋`X-front`（`splitGroup().cut`、`B` 是 null），存檔 `equip.sprite`＝`X-front`、沒有 `back`、不寫 `X-back.png`。已拆好的組切換後按確定：挖除就刪掉後片，前後片就從原圖補一層後片（同一筆 undo）。
  - **線的條件**（`#spCtl`，前後片跟自動面板共用同一塊 DOM，`refreshSpCtl()` 搬到顯示中的面板）：輪廓線＝alpha ≥ 128 而且亮度 < 門檻（`PX.lineTest(c)`，切線帶 `c = {lum}`），預設 24（線稿的黑線約 0～10，暗色內襯約 40 幾，所以預設不能太高）。以前還有 R／G／B 條件和 Alt＋點取色，用不到拿掉了；舊資料的 `c` 只取 `lum`，亮度當時沒勾（null）就用預設 24。共用設定 `S.sp`（`lum`、`cut`、`method`、`close`、`down`、`drop`、`right`、`reach`）存 `localStorage` 的 `paperdoll.split`。**亮度依切割方法各存一份**（`S.sp.lum = {trace, wand}`，`spCrit(method)`）：滑桿、-／+ 改的是目前切割方法那份，切換切割（手動或連動）時滑桿跟切線的 `c.lum` 換成那份；舊格式的 `lum` 是單一數字或 `{on, v}`，兩種方法都用它，沒有時讀更舊的 `paperdoll.splitT`。**色塊**：有切線時在畫布上移動，色塊跟右邊的 `(R,G,B,A)`（`#spRgba`）即時顯示游標底下追線那張圖（`sp.img`）的像素，透明是棋盤格；游標在圖外、離開畫布、沒有切線時清空成 `—`。**-／+**（`.spStep`，`spStep(d)`）：滑桿兩邊，一次 ±1、夾在 0～256，按住 400ms 後每 60ms 連續調，重新追線，跟拖滑桿一樣一整段只記一步（`m.tRec`）。
  - 追線（`PX.splitTrace()`）：從起點往上、往左掃到輪廓線（見上面的條件；全部沒勾就報錯），上線當成「每一直行一個 y」往左右推、左線當成「每一橫列一個 x」往上下推：每一行只在照前緣斜率預測的位置附近找線段，線段突然變很長＝跟岔線（例如帽帶下緣往下接耳罩的邊）併在一起，改用預測對得上的那一側邊緣，所以岔線走不進去。點取在線靠起點那側的邊上，線留給前片。往外走的（上線往右、左線往下）前片那側碰到透明或走到圖邊（裁到剛好的零件外框貼著圖邊）就停、直直延伸出圖；後片那側是開口（透明，例如新頭盔內襯下面）時繼續沿線外緣走，不然延伸線會切過前片還沒走完的線（護頰的黑線），走進開口後線斷了也算走到外面；往內走的（上線往左、左線往上）碰到另一條線就停，兩端在轉角接起來。結果是後片（右下那塊）的多邊形，RDP 簡化（0.75px）。（以前挖除也走這裡、多一條下線，有了魔術棒後拿掉了。）之前試過沿中心線轉角度走，路口那團比較寬的黑色、縮小後只剩 1～2px 的斜線都會讓它轉錯岔路，在不同縮放下結果不一致，才改成函數式的推法。
  - 起點（青色十字）預設是不透明範圍正中央那一直行上、中央所在（落在線上就取線下面）那段線圍起來的區域的中點，離上下的線都遠一點；拖十字移動起點、改門檻都會重算並直接覆蓋多邊形。多邊形用多邊形裁切那套操作改：拖頂點、點邊插點；刪點＝游標停在頂點上（放大標示，`poly.vert`）按 Delete／Backspace，或 Alt＋點頂點（`spDelPt()`），最少留 3 點，各記一步。
  - **畫線標記**（`#spCtl` 的「✎ 畫線」勾選＋筆刷 1～8px＋「清除標記」，前後片跟自動共用）：線斷掉或暗色內襯被當成線時，直接在追線那張圖（`sp.img`）上塗標記，`sp.mark`（`Uint8Array`，每格 0＝照亮度、`MARK_ON`＝強制是線（不看 alpha）、`MARK_OFF`＝強制不是線）傳給 `splitTrace()`／`splitFlood()` 蓋過 `lineTest()`，不改圖片。開著時（B 切換，`[`／`]` 調筆刷）：左鍵＝加線（洋紅）、Shift＋左鍵＝去線（青色）、右鍵＝清掉標記，不能拖起點、頂點、零件；標記一直半透明疊在圖上。一筆（按下到放開，真的改到才算）一步、放開才重新追線並覆蓋多邊形，全清就變回 `null`；「清除標記」一步清光。寫入時才複製（一筆換一個新陣列），所以步驟裡直接放參照。確定時存成 `split.mark = {on, off}`（各是 `[起點, 長度, …]` 行程編碼，`PX.markPack()`／`markUnpack()`），再進來尺寸對得上才帶回；mask 重播不看它（只存多邊形），舊資料沒有就是沒標記。
  - 模式內 undo：拖一次頂點、插一個點、刪一個點、拖一次起點、拉一次滑桿、畫一筆線各一步（`splitState` 記多邊形／起點／門檻／標記／錯誤訊息，最多 50 步），Ctrl+Z／Ctrl+Y 一步一步退，退到底停住、不走全域 undo。有改過時切換圖層／模式會 `confirm` 問要不要套用，關分頁也會擋。
  - 追線那張圖（`mode.img`）是原圖跑到 `splitAt()` 的樣子：一般圖層＝原圖現在的樣子，mask 接在最後；自動零件＝裁切後、縮小前（`autoBase()` 那步之前），mask 插在縮小前面，所以線條比較粗、追得準，改 scale% 也不用重拆。模式裡顯示原圖、藏起前後片，多邊形照原圖擺放縮 `mode.vk` 倍畫（`mode.view` 是借原圖擺放的假圖層，`toWorld`／`toLocal`／多邊形操作都用它）。
  - 確定（`splitApply()`）：前後片的步驟＝原圖步驟在 `splitAt()` 插進 `mask(挖掉)`／`mask(keep)`，都不 trim，三層同尺寸，擺放、不透明度照原圖；mask 帶 `split = {gid, x, y, c, cut?, close?, drop?, w, h, n}`（起點、線的條件、挖除、閉運算、往下射、追線那張圖的尺寸、mask 後面原本跟著幾步；舊資料只有門檻 `t` 就當只勾亮度，舊挖除的 `over` 不用、沒有 `close`／`drop` 就用預設 10／20），靠 gid 認一組（`splitGroup()`），跟著 ops 存進專案。原圖隱藏、選前片，整個動作記一筆群組 undo。`splitSrc` 不進快照，undo／撤掉後也留在原圖上（前後片都沒了就不算一組），再拆沿用它的 gid。
  - 再進來：選三層哪一層按「前後片」都是調原圖；追線那張圖尺寸跟 `split.w/h` 一樣就帶回原本的多邊形和起點門檻，不一樣（原圖裁過）就丟掉、從預設起點重追。確定時照原圖現在的步驟重產前後片，所以拆完後再改原圖（修補、裁切…）重進按確定就會帶進去。前片或後片自己在拆完後又疊了步驟（mask 後面的步數 ≠ `split.n`，`splitOwn()`）就擋下（要重拆先 undo）；前片或後片被刪掉就當成重拆，確定時從原圖補一層。原圖被刪掉：前後片還能存（不寫原圖 PNG），但不能再進來調。「撤掉前後片」：刪前後片、原圖重新顯示並選取，記一筆 undo。
  - **擺放連動**（`linked()`）：三層任一層拖曳、Shift+R 轉、方向鍵、改面板 x/y/a/ox/oy，三層一起改、一起記一筆 undo。
  - **自動模式的頭盔切線**（`mode.sp`，欄位同前後片模式，編輯共用 `editSp()`／`spBefore()`／`spCommit()`）：自動面板的頭盔 radio `不拆／前後片／挖除`（預設前後片，存在 `S.auto.split` 的 `'none'|'split'|'cut'`，舊的 `true/false` 照轉，跟著 `localStorage` 和 `settings.auto`）決定要不要拆、怎麼拆，亮度門檻、切割方法、閉運算、往下射／往右射跟前後片模式共用（連動規則也一樣，每次進自動模式照 radio 套連動）；不是不拆的話，進自動模式時 `autoPlan()` 先去綠、算好零件範圍，頭盔那塊裁好（縮小前）馬上用預設起點＋門檻追線，切線畫在原圖的頭盔上（`autoSpView()` 用原圖擺放換算到裁切範圍）；拆之前切換由 `autoSpSync()` 立刻追線或丟掉（前後片↔挖除記一步，undo 時 radio 跟著退）。拖起點、拖頂點、點邊加點、刪點、畫線標記、線的條件都能調，每個動作各一步（模式內 undo）。只有點到起點／頂點／邊才改切線，其他照舊拖零件。按確定時頭盔有切線就一起拆成 `-front`／`-back`（挖除只有 `-front`；同一筆 undo、選前片），追線失敗就只拆零件、狀態列寫原因。**拆完就丟掉 `mode.sp`、不再顯示切線**，radio 和線的條件反灰；之後再進自動也不畫，要調切線或補拆去前後片模式。
  - **魔術棒**（`PX.splitCut()`，以前叫「淹水」）：切割選魔術棒時 `#spCtl` 多一列 `閉運算 [k]　☑ 下 [X]　☐ 右 [X] px`（`#spCutRow`，預設 10／勾 20／不勾 20，k 填 0＝關掉，上限 30／50／50；不勾＝不射、X 留著；切線帶 `close`／`down`／`drop`／`right`／`reach`，只有魔術棒才存進 `split`，舊資料沒有 `down` 當勾、沒有 `right` 當不勾，改了記一步、重算）。舊 mask 沒有 `method`：挖除而且有 `close` 當魔術棒，其他當沿線。`PX.splitFlood()` 四步：淹水＝從起點 4 方向淹，碰到輪廓線或透明就停（4 方向，1px 的斜線才擋得住）；閉運算＝R 膨脹 k 再侵蝕 k（方形、橫直分開、四周先補 k 格免得貼圖邊的被侵蝕掉），填平寬 ≤ 2k 的縫（連著牆的半島、孤島）；往下射＝R 每一直行的下緣往下 X px 內碰到透明／圖邊，才把中間（線＋外緣反鋸齒，不看是不是線）收進來，線外是前片（例如皮帶）就不收；往右射同一套規則（`reach()` 共用），從往下射之後的 R 每一橫列右緣往右看，所以往下收進來的那幾列也會往右射、右下角的轉角收得到。射線只直走：照字面「往下穿線」的方向性淹水穿過線後會轉彎漏進前片。然後取起點那一塊（4 連通），沿格子邊順時針描**外圈**（裡面的洞一起挖），閉合的環從離起點最遠的點切兩段各自 RDP（0.75px），結果照舊是一個多邊形，可以拖頂點、點邊加點。再進來照存檔帶回多邊形，拖起點／改條件才重算。往右試過「只收緊鄰的線」，皮帽這種右邊是護耳的頭盔會把護耳內側的線吃掉，所以跟往下一樣要 X 內碰到透明才收，而且預設不勾。
  - 自動模式拆出的零件可以再拆前後片：前後片跟著零件搬（拖曳／點選前後片也算點到零件、方向鍵、改 x/y）、一起進模式內 undo、改 scale% 一起重播、「取消」自動時一起刪；選前後片按「自動」等於選零件。
  - 舊格式（前片就是原圖本身加 mask，`split` 沒有 `w`）不認：進前後片模式只提示要先 undo 或刪掉重拆，存檔、連動都當作一般圖層。
- **icon 模式**：作用在選取的單一圖層，面板 `尺寸｜角度｜佔比%`（全域設定，存 localStorage `paperdoll.icon`，預設 `100｜45｜90`，不合法的數字不收）＋預覽框。`iconOf()`：來源圖順時針轉 a 度（畫到剛好裝得下的畫布）→ 裁到不透明範圍（trim 門檻）→ 等比縮放、長邊＝尺寸×佔比 → 置中放到 尺寸×尺寸。來源（`iconSrc()`）：自動零件用縮小前的圖（`autoBase()` 那步之前，`paint` 不算），其他圖層用目前的樣子；預覽照圖層的 canvas 快取來源。「存檔…」走一般存檔對話框，預設圖層所在目錄、檔名 `<圖層名>-icon`，只存 PNG，半透明圖層有「烘入不透明度」勾選。取代以前的「匯出 icon」（壓平所有顯示中的圖層、不旋轉）。自動模式存武器的 `-icon` 也用 `iconOf()`，但數字固定 `ICON_AUTO`，不看這裡的設定（見上方自動模式的武器）。
- **擺放是數字**：`x`／`y`／`a`（角度）／`ox`／`oy`（中心點）不烘進圖。自動拆的裝備由「存到 item…」直接寫進 `item.json`（見下方「遊戲資料」）；一般存檔的擺放存在同名 `.json`。
- **世界座標＝圖片像素**；遊戲單位＝世界座標 × scale（全域，預設 0.25）。「套用 scale」只切換顯示的數字單位與預覽大小，不動像素。
- **內容不跳位**：裁切、trim、改中心點時會自動補償 `x`／`y`；縮放以中心點為基準，`x`／`y` 不變。縮放面板的 % 以原圖為 100（`srcScale()`＝ops 裡所有 `xform` 的 `w/sw` 連乘，裁切不算），寬／高是目前的像素。

## 跟遊戲的對應

遊戲組零件在 `src/components/view.js` 的 `_addPart`（以及 `src/roles/dummy.js` 的 `ghost`）：

```js
sp.setScale(part.scale);
sp.setOrigin(part.ox ?? 0.5, part.oy ?? 1);
sp.x = part.x ?? 0;  sp.y = part.y ?? 0;  sp.angle = part.a ?? 0;
```

`equip.back`（前後片的後片）用同一組 `scale`／`x`／`y`／`a`／`ox`／`oy` 再畫一張，深度 `PART_DEPTH[GM.PART.BACK]` = 1.5（護甲 1 ＜ 後片 ＜ 頭 2；前片照頭盔 3）；背包紙娃娃（`uiclass.js`）、角色編輯器預覽、試穿工具都照這個畫。

`x`／`y` 是零件中心點在角色 view 容器裡的位置。容器 (0,0) 是角色框（`w`×`h`）的中心；`anchor`（預設 0,16）是角色在地圖上的站立點，剛好是腳下那格 tile 的中心。「顯示 origin」勾選時，每個顯示中的圖層都畫出中心點十字（選取中＝黃、其他＝橘）。工具畫布上的參考線：紅十字＝(0,0)、白虛線＝角色框、藍框＋圓點＝anchor 那格 tile，數值可在上方調整。參考框的數字是「顯示單位」：沒勾 scale 時是圖片像素，勾了是遊戲像素，所以 tile 在畫面上的大小不隨勾選改變，變的是圖層。

## 檔案

- 開檔：工作資料夾固定是專案的 `images/`（殼選了專案資料夾就自動設好），從左側清單點 PNG；或從檔案總管拖 PNG（可連同名 `.json`）進畫布。有同名 `.json` 就套用裡面的擺放。
- 清單（含存檔對話框）的 PNG 有 32×32 縮圖：裁掉透明邊（alpha < `AUTO_ALPHA` 不算）再縮，捲到看得見才產（`IntersectionObserver`），依路徑快取、`lastModified` 變了重產；存 PNG／icon 後會重畫已載入的縮圖，⟳ 清快取重建。專案檔不放縮圖，同寬空位裡放 🧩。
- **刪除＝移到 `.tbd`**：一般位置的檔案／資料夾右鍵是「移到 .tbd」（`fileToTbd()`／`dirToTbd()`），`images/.tbd/` 底下的才有真的「刪除」跟「搬回原位」（`fileBack()`／`dirBack()`）。`.tbd` 本身跟根節點一樣只有「新增資料夾」（不能改名、刪除、移到 .tbd）。
  - 移到 .tbd：保留相對路徑（`a/b/x.png` → `.tbd/a/b/x.png`、資料夾 `a/b` → `.tbd/a/b`），中間缺的資料夾自動建；png 連同名 `.json`。撞名就合併＋覆蓋（資料夾整棵合併進去）。只有兩種情況 `confirm()`：`.tbd` 裡有檔案會被覆蓋（`overlap()` 列出來）、有專案用到要搬的圖（資料夾的話只算資料夾外面的專案）；其他直接搬。引用當成刪除：開著的圖層脫鉤（`forgetFile()`／`forgetDir()`），專案檔不改。資料夾用建新的 → `FS.copyDir()` → 刪舊的（同改名），複製失敗舊的不動、刪舊的失敗留兩份提示自己刪。
  - 搬回原位：去掉 `.tbd/` 搬回去，中間缺的資料夾自動建；原位已有同名（檔案連 `.json`、資料夾比同層的資料夾或檔案，大小寫不分）就整個拒絕，不覆蓋。不碰引用：開著的圖層不會接回去，但專案檔沒改過，重開就對得上。
  - `.tbd` 裡搬回原位或刪除之後，往上清掉 `.tbd` 裡空的資料夾（`pruneTbd()`，`.tbd` 本身留著）。這些操作都用 `reloadUp()` 由上往下重列來源跟目的地的上層節點（新建的中間資料夾才會出現、被清掉的跳過）。
- 主清單的資料夾列右鍵「新增資料夾」「改名」「移到 .tbd」（`.tbd` 裡是「刪除」「搬回原位」；根節點只有新增）；存檔對話框路徑旁有「新資料夾」按鈕（建在目前的目的地底下）。
  - 拖曳搬資料夾（`moveDir()`）：資料夾列拖到別的資料夾列上放開（根節點、`.tbd` 本身不能拖，一次一個，不跟檔案多選混用）；拖進自己或自己底下拒絕、原本就在那裡不動、目的地有同名（資料夾或檔案，大小寫不分）拒絕，不 confirm。搬法跟引用更新同改名（共用 `relocateDir()`）；拖進 `.tbd` 也是一般搬移（引用跟著改，不是脫鉤）。
  - 改名（`startRenameDir()`／`renameDir()`，搬移核心 `relocateDir()` 跟拖曳共用）：資料夾列原地編輯（保留 ▸／▾），名稱規則同新增，只改大小寫拒絕。FS Access 沒有搬資料夾，所以是建新的 → `FS.copyDir()` 整棵複製 → 刪舊的：複製途中失敗就刪掉複製一半的、舊的不動；刪舊的失敗（被鎖住）就留著兩份、狀態列提示自己刪，引用照樣改成新的。引用：所有 `.pdproj.json` 圖層的 `src`／`path`、開著的圖層 `srcPath`／`path`／`dir`、專案歸屬 `proj.path`／`proj.dir`（舊 handle 失效，重新 resolve），比對不分大小寫、路徑等於或在它底下；縮圖快取清掉那些路徑；原本沒有未存修改就重設比對基準。改完重列上層，改名的資料夾變回收合。不能 undo。
  - 新增（`startNewDir()`）：展開那個資料夾、最上面插一列輸入框，預設「新資料夾」全選，Enter 建立、Esc／失焦取消（在存檔對話框的 form 裡要 `preventDefault`，不然 Enter 送出、Esc 關掉對話框）；空的、`\/:*?"<>|`、全是 `.`、跟同層資料夾或檔案撞名（大小寫不分）都拒絕；不支援 `a/b` 多層。建好重列那個節點；存檔對話框另外選新資料夾當目的地、游標回檔名欄（`treeDir()` 照路徑一層層展開找節點）。
  - 刪除（`deleteDir()`，只在 `.tbd` 裡）：每次都 `confirm()` 列出檔案數（遞迴）跟資料夾外面用到裡面圖的專案，確定才整棵刪（`removeEntry(…, {recursive: true})`）。開著的圖層脫鉤（`forgetDir()`）：原圖在裡面的清掉 `srcPath`、專案檔在裡面的 `proj` 清掉（標未存）、存檔位置在裡面的回到工作資料夾（`dir: null`）；縮圖快取清掉那些路徑；外面的專案檔不改（開的時候照舊提示找不到原圖）。新增、改名、移到 .tbd、刪除都不能 undo。
  - 資料夾節點（`.tdir`）上掛 `fsDir`（handle，不能叫 `dir`，會撞到 HTMLElement 的文字方向屬性）、`depth`、`expand()`（回傳列目錄的 promise，剛展開還沒列完時也會等它，`treeDir()` 靠這個）。
- 主清單的檔案列右鍵選單「改名」「移到 .tbd」（`.tbd` 裡是「刪除」「搬回原位」；存檔對話框的樹沒有）。png 連同名 `.json`（載入時讀的擺放資料）一起改名／搬／刪除。
  - 改名：原地編輯不含副檔名，Enter 確定、Esc／失焦取消；撞名（含 `.json`）、`\/:*?"<>|`、只差大小寫都拒絕。FS Access 的 `move()` 不是每個環境都有，`FS.renameFile` 是複製再刪。掃 `images/` 底下所有 `.pdproj.json`，把指到舊路徑的 `src` 換掉寫回；開著的圖層 `srcPath` 跟著換、圖層名等於舊檔名也一起改；改名專案檔則改開著的圖層的 `proj.name`。不碰 `textures/` 跟 item.json／role.json。
  - 刪除（只在 `.tbd` 裡）：`confirm()` 列出同名 `.json` 跟用到這張圖的專案（專案檔不改，開的時候照舊提示找不到原圖）；開著的圖層留著、清掉 `srcPath`（之後當拖進來的圖）；刪專案檔則圖層跟專案脫鉤、標未存。
- 主清單多選＋拖曳搬檔（`treeOpt.move`；存檔對話框的樹沒有；資料夾的拖曳見上面）：
  - 選取：Ctrl+點切換（不開圖）、Shift+點從上次點的那列加選到這列（同資料夾才算範圍，跨資料夾只切換那列）、一般點照舊開圖並清掉選取；可以跨資料夾選；Esc、資料夾節點重列（`reload()`，含 `tools:images` 推播）、整棵重建都清掉選取。右鍵選單只作用在那一列。
  - 拖檔案列到資料夾列上放開（根節點也行）：拖的那列有選就搬整批，沒選就只搬它；原本就在目的地的跳過。畫布不接清單拖來的列（只收檔案總管的檔）。
  - `moveFiles()`：png 連同名 `.json` 一起搬（`FS.moveFile` 複製再刪）；先整批檢查撞名（目的地已有、或選到的彼此同名，大小寫不分），有任何一個就整批不搬、狀態列列出；途中出錯就停，回報已搬的。參考更新同改名：所有 `.pdproj.json` 的 `src`、開著的圖層 `srcPath`；搬專案檔則改開著的圖層的 `proj.dir`／`proj.path`。不碰 `textures/` 跟 item.json／role.json。
- 清單自動更新：`images/` 有變動時 vite dev 推 `tools:images`（見 [tools-shell.md](tools-shell.md)），`imagesChanged()` 只重列 `dirs` 裡「列過」的資料夾節點（`.tdir` 的 `reload()`；路徑不分大小寫），子資料夾節點沿用、展開狀態跟捲軸都留著，檔案列重建；`changed` 只重畫縮圖。存檔對話框開著時它的樹也一起更新。畫布上已經開著的圖層不管（原圖在外面被改／刪也不動）。紙娃娃自己存的檔也是靠這個出現在清單裡。⟳ 留著手動整棵重建。
- 左右側欄跟畫布之間有分隔線：拖曳改寬（150～600px）、雙擊回預設（230／290），寬度記在 `localStorage`（`paperdoll.leftW`／`paperdoll.rightW`）。
- 存檔：每層各自存，預設目錄是工作資料夾的 `output/`（沒有就用圖層所在目錄）、預設檔名 `原檔名-copy`，同名會問是否覆蓋；同時寫 PNG 和 `.json`。
  - **匯出到 textures/**：「存檔…」跟 icon 的「存檔…」（`saveDialog(..., tex = true)`）的樹多一個 `textures` 根（`S.assets.tex`，預設摺起來，第一層不列 `TEX_SKIP` 的 `.tbd`／`minimap`，`treeNode()` 的 `opt.skip`），選它底下的資料夾時結果 `tex: true`、`path` 相對 textures/、對話框路徑顯示 `textures/...`；「新增資料夾」照選到的那個根建。存進去前用 `texKeys()` 查撞名：**別的資料夾**已經有同 key（不分大小寫）就 alert 並重開對話框讓你改檔名，同資料夾照舊問覆蓋。存進 textures/ 是匯出：只寫 PNG（不寫擺放 `.json`），圖層的 `dir`／`path`／`srcPath`／步驟／不透明度都不動，狀態列「已匯出 textures/...」；圖片清單由 dev server 監看 textures/ 自己重產。存專案不能選 textures/。存檔不會自動 trim（以前的「存檔時自動 trim」拿掉了，舊專案的 `settings.autoTrim` 直接忽略），要裁就先按「裁到剛好」。
- **遊戲資料**：只有自動模式的「存到 item…」會寫（見上方自動模式），一般存檔只存工作資料夾（以前的「存到遊戲資料」勾選拿掉了，角色零件的擺放用試穿分頁調，見 [fit-tool.md](fit-tool.md)）。
  - 兩個資料夾都從殼給的專案根目錄推出來：工作資料夾＝`images/`（開圖、存專案、一般存檔），遊戲資料＝`public/assets`（要有 `json/item.json` 和 `textures/`，不對就在狀態列提示）。寫了 `item.json` 會廣播給其他分頁（見 [tools-shell.md](tools-shell.md)）；道具編輯器開著也沒關係，它存檔前會偵測到這裡寫過並三方合併。
  - 擺放：`scale`／`x`／`y` 照寫，`a`／`ox`／`oy` 是預設值（0／0.5／1）就刪掉那個 key、否則寫入（`writeEquip()`），其他 key（`ext`、`hideHair`…）不動；`drop.scale`＝`equip.scale`，`drop.sprite` 是完整的圖 `X`（掉在地上的樣子，`src/items/pickup.js` 讀 `drop.sprite ?? icon`）。整份 `JSON.stringify(…, null, 2)` 重寫。存在工作資料夾外面，所以不會「改以剛存的檔當原圖」，原圖跟步驟留在專案裡。
  - PNG 是新建的（原本沒有同名檔）時狀態列提示：要按殼的「更新圖片清單」重產 `textures.json`，遊戲才載得到（不自動按）。檔名就是 texture key，整個 `textures/` 不能撞名，撞了更新清單會報錯。
- 不透明度：平常只影響顯示（存在專案裡，不進 `.json`）。圖層不透明度 < 100% 時，存檔對話框多一個「烘入不透明度」勾選（預設勾），勾了 PNG 的 alpha 會乘上它。存檔觸發「改以剛存的檔當原圖」且有烘入時，opacity 會歸 1（不然會乘兩次）。
- `.json`（sidecar，給人看的，遊戲不讀）：

  ```json
  { "x": -3, "y": 6.75, "a": 30, "scale": 0.25, "ox": 0.5, "oy": 1 }
  ```
- trim 門檻（工具區「門檻」欄，預設 16）：alpha 低於門檻的像素不算內容，「裁到剛好」、自動模式分塊、icon 共用。AI 圖外圍常散著 alpha 個位數的雜訊，門檻設 1 會被它們卡住裁不進去；門檻只影響邊界計算，範圍內的淡像素不會被清掉（要清用「清除透明」）。
- 專案（`*.pdproj.json`）：記每層的原圖路徑（相對工作資料夾，`src`）＋原圖尺寸、步驟清單 `ops`、擺放、顯示／鎖定／不透明度、圖層順序，以及上方的設定；undo 紀錄不存。
  - 開啟：左側清單點 `.pdproj.json`。畫布空的就直接開；已有圖層時問「加入／取代／取消」。取代＝清掉目前圖層、套用專案設定、清空 undo（有未存修改會先問）；加入＝疊在最上面、保留原座標、不重新置中、設定沿用目前的（scale 不同會 alert 警告），可以 undo（結構快照）；同一個專案（路徑相同）已經開著就不能再加入。
  - 圖層歸屬：每層的 `proj`（`{dir, path, name}`）**只在開專案時設定**，存專案永遠不改。複製／裁切到新圖層沿用來源層、合併沿用最底層、點 PNG／拖進來的沿用選取圖層（沒選取就是無）。畫布上有哪些專案是從圖層的 `proj` 算出來的。
  - 存專案：只存圖層清單最左邊 💾 打勾的圖層（`save`，預設勾、不進專案檔；hover 顯示所屬專案；全沒勾時按鈕停用），沒有 Ctrl+S。預設檔名：畫布上剛好一個專案＝它，否則 `project`；可以選工作資料夾裡任何專案覆蓋，覆蓋時如果 💾 的圖層跟那個專案的圖層（`proj` 指向它的那些）不是同一組，確認視窗多一行提示。
  - 標題（工具列小字與分頁標題）列出畫布上的專案（`body + sword`）；`*` 是整個畫布跟上次開／存時比對出來的，存到哪個專案都會清掉。加入專案時，原本沒有未存修改才會重設比對基準。
  - 拖進來的圖沒有原圖路徑，存專案前要先「存檔…」存進工作資料夾。圖層存檔時如果原本沒有原圖路徑、或覆蓋了自己的原圖，會改以剛存的檔當原圖、步驟歸零、清掉這層的 undo（不然步驟會被套用兩次）。
  - 開專案時原圖找不到就略過該層並警告；原圖尺寸跟存檔時不同也會警告（步驟是照舊尺寸記的，結果可能不對）。覆蓋原圖會影響引用它的其他專案。舊專案設定的 `iconSize` 直接忽略。
- 關閉（`closeAll()`，「存專案…」旁、沒圖層時停用）：一次清掉全部圖層（不分專案、拖進來的也清），有未存修改先 `confirm()`；清空 undo、標題回「（未命名）」；scale／tile／角色框／anchor／自動模式等設定不動。
- 參考人偶：圖層列右鍵標成 `男／女` 的 `髮／頭／身體`（圖層 `tag`＝`m-hair`／`m-head`／`m-body`／`f-…`，名字前顯示 `♂髮` 之類徽章，選單有「取消標記」），同一個 tag 只能一層，標新的會拿掉舊那層的。header 的 `男｜女`＋`☐ 頭髮`（`S.doll = {sex, hair}`，沒有標記圖層時停用）按下去是當下批次改 👁 一次（`setDoll()`：選中性別的頭／身體顯示、髮照勾選，另一性別全藏，沒標記的不動），之後手動 👁 照常；跟 👁 一樣不進 undo、標記本身也不進 undo。`tag` 跟著專案圖層存讀、`doll` 存在專案 `settings`；`cloneAbove()`（複製、自動零件…）跟合併出來的新圖層不帶標記；加入專案時 tag 跟現有圖層撞到就拿掉新那層的並警告。

## 程式結構

| 檔案 | 內容 |
|---|---|
| `main.js` | 狀態、繪製、滑鼠鍵盤、模式（移動／裁切／縮放／清除透明／顏色／移除綠色／變形／自動／像素／前後片／icon）、UI 同步、開存檔 |
| `pixels.js` | 純像素運算：xform（平滑模式先每次縮一半到兩倍以內）、compose、warp、replay、erase、mask、alphaClear、fill、key、removeGreen、paint、opaqueBounds、blobs（連通塊）、splitTrace（前後片追線）；工具建的 canvas 都是 `willReadFrequently`（getImageData 快很多） |
| `history.js` | 全域 undo／redo（快照 x/y/a/ox/oy/ops/canvas 參照；合併用的圖層清單結構快照） |
| `../common/fs.js` | 列目錄、讀寫檔；跟道具編輯器共用 |
| `../common/shell.js` | 跟殼的接線：收專案資料夾、寫 json 後廣播、回報未存狀態 |
