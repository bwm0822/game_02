# 紙娃娃編輯器（tools/paperdoll）

用來調整紙娃娃零件圖（身體、頭、裝備、武器）的大小與位置，讓它們疊在一起對得上。

開啟：`npm run dev` 後瀏覽 `http://localhost:8080/tools/` 的「紙娃娃」分頁（殼見 [tools-shell.md](tools-shell.md)；只支援 Chrome／Edge，用 File System Access API 讀寫檔案）。正式 build 只打包 `index.html`，工具不會進遊戲。

## 設計原則

- **像素操作永遠從原圖算**：每層保留原圖 `src` 和步驟清單 `ops`，畫面是「原圖依序重播 ops」的結果，存檔時才把結果烘進 PNG。步驟有九種：`xform`（取輸入的小數範圍縮放成 w×h，「保留框內」裁切／縮放／trim 都是它）、`erase`（把 x,y,w,h 挖成透明，「移除框內」裁切，尺寸與 `x`／`y` 不變）、`mask`（多邊形 `pts:[[x,y]…]`，`keep` 時只留多邊形內、否則挖掉多邊形內；反鋸齒、nonzero 填色，尺寸不變）、`alpha`（清除 alpha < t）、`fill`（alpha ≥ t 的像素整組換成 r,g,b,a）、`key`（RGB 完全等於 r,g,b 的像素變透明，不看 alpha）、`removeGreen`（綠底去背：`G > 100` 且比 R、B 都大 `rgbThr`，或不透明像素的 HSV 落在範圍內，就變透明；「移除綠色」模式）、`warp`（網格變形）、`paint`（像素修補 `px:[[x,y,r,g,b,a]…]`，那格直接換成這組 RGBA）。相鄰的 `xform` 會合成一個（`compose()`），相鄰的 `alpha` 取較大的 t（`fill`／`key` 不合併，顏色不同就是不同步驟），所以「縮放 → trim → 再縮放」只會從原圖取樣一次；只有中間夾著其他種步驟時才會分成兩段。
- **網格變形（多框）**：一步 `warp` 記一組框 `frames:[{x,y,w,h,cols,rows,pts}]`，矩形是變形前那張圖的整數座標（限制在圖內），`pts` 是每個格點變形後的位置（同一套座標，可超出原圖）。`warpFrames()` 依序處理每個框：從目前結果取出框內、挖掉、貼上框內變形後的圖（重疊的框吃前一個框的結果）；輸出畫布涵蓋原圖和所有 `pts`，(0,0) 對應 `warpFramesBounds()` 的 `bx,by`。框內變形用 `warp()`：每格拆兩個三角形，逐像素以仿射反查、預乘 alpha 雙線性取樣。舊格式（整張圖一張網格 `{cols,rows,pts}`、沒有 `frames`）照樣重播，接著編輯時轉成一個整張圖的框。
  - 操作：拖曳空白處拉出新框（格數取面板，預設 4×4），點框切換目前的框（重疊時往下輪），拖框外的小方塊調大小（點等比例跟著、已做的變形保留），Delete／Backspace 刪目前的框。目前的框白框＋青網格＋控制點，其他框灰色、不顯示點。控制點：拖曳移動選取的點；Shift+拖曳框選加選、Ctrl+拖曳框選取消，Shift／Ctrl+點單點加選／取消；拖點時按著 Shift 只沿水平或垂直（螢幕方向，圖層有旋轉時換回圖片座標）；方向鍵微調。框開始拖點之後要先「重設」才能改格數。
  - 套用：「確定」（Enter）把框寫成一步 `warp`（沒變形也沒步驟的框不寫）。
  - undo：每個框有自己的步驟 `hist`（改之前的樣子，最多 50 步）和 `fut`（redo）。`warpRecord` 記目前這框：拖點／把手（一次拖曳一步）、方向鍵、重設格數。`hist` 跟著框寫進 op（`frames[i].hist`），所以確定後再進來、存專案再開都還能退；`fut` 不存。變形模式裡 Ctrl+Z／Ctrl+Y 只動目前的框：退到剛拉出來的樣子（沒變形）再按就拿掉這個框、換上一個框；一個框都沒有時依序救回 Delete 掉的框（`deleted`，只在這次模式裡）；再沒有就停住，不走全域 undo（要退更早的操作先離開模式）。拿掉／救回框的 redo 記在 `frameRedo`，Ctrl+Y 先 redo 目前這框，再處理它。離開模式時整段只記一筆全域 undo。切換圖層／模式時有沒套用的修改會 `confirm` 問要不要套用（取消＝放棄），關分頁也會擋；Esc／取消鈕直接放棄。
  - 最後一步是 `warp` 時再按「變形」會拿掉它、重播出變形前的圖並接著編輯同一組框（變形前的 `x`/`y` 由 `bx,by` 反推），所以不會累積取樣；但之後又 trim／裁切過，後面多了 `xform`，再變形就是新的一步 `warp`。編輯中的預覽就是最後結果（直接改圖層的 canvas／x／y），取消時用快照還原。
- **undo**：Ctrl+Z／Ctrl+Y，快照只存 `ops`、`canvas` 的參照和擺放數字；兩者都不會被就地修改（每次操作換新的），所以快照不用複製像素。合併用「結構快照」（`snapList`：`S.layers` 複本＋`S.active`），被合併的圖層物件原封不動、也不 `forget`，換回清單就還原；刪除圖層時會把它從結構快照裡拿掉（不然 undo 合併會讓它復活）。刪除、拖曳排序本身仍不能 undo。
- **合併圖層**：「向下合併」（Ctrl+E，選取層＋正下方那層）、「合併可見」（Ctrl+Shift+E，顯示中且沒鎖定的全部）。用 `flatten()` 壓成一張新圖層，放在最底層的位置、名字 `底層名-merged`、沿用底層的 `dir`/`path`；旋轉烘進像素（`a=0`），中心點的世界座標沿用最底層的（`x`/`y` 不變、重算 `ox`/`oy`）。有半透明圖層時用 `confirm` 問要不要烘入不透明度（取消＝照 100% 合）。向下合併遇到隱藏／鎖定的圖層會拒絕。新圖層沒有原圖路徑，跟拖進來的圖一樣要先存檔才能存專案。
- **複製圖層**：「複製」（Ctrl+J）把選取層淺拷貝一份（`ops`／`canvas`／`src` 共用參照，反正不會就地修改），放在它正上方、名字 `原名-copy`、原圖路徑相同；用結構快照所以能 undo。
- **裁切四種模式**：保留框內（`xform`）、移除框內（`erase`）、移到新圖層、複製到新圖層。後兩者先複製一層（同上，但名字沿用原名）再對副本做 `xform`，所以副本也是從原圖只取樣一次、內容不跳位；「移到」另外在原圖層加 `erase`。這一步同時改圖層清單和原圖層像素，用群組快照（`{group: [snapList, snap]}`），一次 undo 全部還原。
- **多邊形裁切**：裁切面板選「多邊形」後，四種模式照樣用（`cropSel()` 依形狀回傳 `keep`／`cut`）：保留＝`mask(keep)`＋裁到外接矩形的 `xform`（往外取整、限制在圖內，頂點可以點在圖外）；移除＝`mask(挖掉)`。單擊加點、點第一點或雙擊閉合、Backspace 倒退（已閉合就先解開）、Shift 讓這一邊鎖 45°；閉合後拖頂點、點邊插點（同一下直接拖），點空白不做事；Esc 先清掉選取（矩形也是），再按一次才離開模式。頂點存圖層本地座標，容錯 8 螢幕 px。反鋸齒的邊在「移到新圖層」疊回去時 alpha 會略低一點（一般 over 合成不是相加），縮小後看不出來。
- **顏色模式**：「填色」「去色」共用一個色票，即時預覽、確定才寫入步驟。點畫布是滴管，吸選取圖層（目前步驟的結果）的 RGB 填進色票；填色的 alpha 欄不跟著吸，免得吸到半透明邊緣把它改掉。去色是完全相等，所以背景色要用滴管吸，不要用色票挑。
- **自動模式**：把一張 AI 產的綠底整套圖（頭盔左上、護甲左下、靴子右下）拆成零件。面板三行（零件／象限／scale%／x／y，x/y 是遊戲單位），改了寫進 `localStorage`（`paperdoll.auto`）並跟著專案設定 `settings.auto` 存讀，「還原預設」回到程式裡的 `AUTO_DEF`。進模式時什麼都不動（只是讓你先調數字），按「確定」才 `autoSplit()`：把每個零件複製一層，步驟依序加 `alpha`（t=32）→ `removeGreen`（同模式預設值）→ 一個 `xform`（裁到零件範圍再縮放，op 上多記 `pct`）。零件會跨過中線（護甲肩膀），所以不切象限：去綠後照門檻把不透明像素分 8 方向連通塊（`PX.blobs()`），比最大塊 1% 還小的當雜點丟掉，其餘依重心落在哪個象限歸給該零件（兩隻靴子是兩塊），零件範圍＝它所有塊的外接矩形（範圍重疊時會帶到別的零件的一角，目前的圖沒有這情況），中心點 `0.5,1`、`a=0`；疊在原圖正上方（由下往上 靴子、護甲、頭盔），原圖隱藏、選取頭盔。沒有塊歸給它的零件略過，一個零件都沒有就只顯示訊息、什麼都不建。拆完記一筆群組 undo（原圖的顯示也記進快照：`hist.snap(L, true)`），**留在模式裡**、「確定」反灰。
  - **一張圖只拆一次**：零件記 `auto = {key, gid}`、原圖記 `autoSrc = gid`，兩個欄位都跟著專案存讀（`cloneAbove()` 複製出來的圖層不帶）。選原圖或任一零件按「自動」，只要畫布上還有這組零件就直接進「調整」（`autoEnter()`）；零件刪光（或 undo 掉）才能再拆，再拆沿用原圖的 `gid`。
  - **調整**：面板顯示這組零件的實際值（scale% 讀 `xform.pct`、x/y 從圖層位置換算），沒有零件的那行反灰。去綠圖（`mode.T`）從第一個零件自己的步驟反推（`xform` 之前那段，第一次改 scale 才 replay），所以原圖被刪了也能調；各零件的裁切框取自它的 `xform`。改數字時 `autoApply()`：scale% 有變才從 `T.canvas` 重做那一個 `xform`（ops 換成 `[...T.ops, xform]`），x/y 只改位置，整行同時寫回全域預設。有 `paint` 的零件改 scale% 會 `confirm` 問要不要清除修補，否＝數字退回。
  - **拖曳／方向鍵**（拆完後才有；還沒拆時點畫布不做事）：等於用滑鼠輸入 x/y（`autoMove()`），步進 1 世界 px、Shift 鎖水平／垂直；拖的時候面板跟著跳，放開時寫回全域預設。點選只看這組零件（`pick(w, only)`，會穿過疊在上面的別的圖層，跳過鎖定／隱藏的），點到的變選取、不離開模式，點空白不做事。方向鍵微調選取的零件（1 px，Shift 10 px），每按一次就寫回預設。
  - **擋下再調**：零件步驟要是 `[...去綠, xform(有 pct), ...paint]`（`autoBase()`）。拆完後再裁切／trim／縮放，新的 `xform` 會跟它合成一步（`PX.compose()` 不帶 `pct`），或後面多了別的步驟，就不能再進自動，要重拆先取消自動。只拖位置不算改過。
  - **按鈕**：「取消」（`autoRevoke()`）＝撤掉這次自動：刪掉整組零件、原圖重新顯示並選取（原圖不在就只刪零件），記一筆 undo；還沒拆時就只是離開。「離開」／Esc（`cancelMode()`）＝保留結果離開。調整中點原圖或這組零件不離開模式，點別的圖層＝離開；刪部分零件就從 `mode.parts` 拿掉（模式內步驟和 `mode.snap` 也用 `History.drop()` 拿掉它，免得 undo 讓它復活），刪光就離開。
  - **undo**：模式內有自己的步驟（`mode.hist`／`mode.fut`，最多 50 步，`autoStep()` 記這組零件改之前的樣子），改一個數字、拖一次（真的動到才算）、按一下方向鍵各一步；Ctrl+Z／Ctrl+Y 一步一步退／重做，並把零件現在的數字寫回全域預設，退到底停住、不走全域 undo（剛拆完按也不會退掉拆）。離開模式時還有步驟才記一筆全域 undo（進調整時的快照 `mode.snap`），拆本身是另一筆，所以離開後先退調整、再退拆；「取消」前有步驟也先記這筆。
- **像素模式**：修縮小後成品的細節（雜點、殘綠、斷線），不是拿來從零畫圖。鉛筆（B）／橡皮擦（E）、方形筆刷 1～8px（`[`／`]`），鉛筆是**取代**成色票的 RGBA（不混色）、橡皮擦是 alpha 0，畫到圖外的直接裁掉；色票跟顏色模式共用（`pxRgb`↔`colRgb` 同步，alpha 是自己的 `pxA`），Alt+點吸 RGB 連 alpha（跟顏色模式不同：修補要的是一模一樣的像素，顏色模式的填色 alpha 則不跟著吸）。筆畫畫在模式的 `preview` 上（每筆只 `putImageData` 筆刷範圍），`map`（`y*W+x → rgba`）是要寫進步驟的內容；確定（Enter）寫成**一步** `paint`、全域 undo 一筆，座標是前面所有步驟跑完那張圖的像素座標；最後一步就是 `paint` 時再進模式會拿掉它、筆畫併進同一步。模式內 Ctrl+Z／Ctrl+Y 一筆一筆退（按下到放開＝一筆，真的畫到圖上才算，最多 50 筆），退到底停住，不走全域 undo；切換圖層／模式時有沒套用的筆畫 `confirm` 問要不要套用，關分頁也會擋。一格像素 ≥ 8 螢幕 px 才畫像素格線，游標畫出對齊格子的筆刷框（鉛筆用色票色、橡皮擦白色）。選取圖層鎖定或隱藏時不能進模式。
  - **有 `paint` 的圖層不能再縮放、變形、自動拆**（`setMode`／`autoEnter` 擋下並 alert；自動拆出的零件有 `paint` 可以再進自動調，見上）：`paint` 記的是某個尺寸下的格子，換尺寸就對不上，而且縮放的 `xform` 會被 `paint` 隔開、合不回前面的 `xform`，修過的像素會被重新取樣。純裁切（保留框內、trim、移到／複製到新圖層）跟其他不重取樣的步驟照順序疊在後面就好。要再縮放就按「清除修補」：拿掉這層所有 `paint`、重播、記一筆全域 undo，模式內還沒確定的筆畫一起丟掉。
- **擺放是數字**：`x`／`y`／`a`（角度）／`ox`／`oy`（中心點）不烘進圖。裝備直接寫進 `item.json`、角色的身體／頭／手／屍體直接寫進 `role.json`（見下方「存到遊戲資料」）；配不到的零件存在同名 `.json`。
- **世界座標＝圖片像素**；遊戲單位＝世界座標 × scale（全域，預設 0.25）。「套用 scale」只切換顯示的數字單位與預覽大小，不動像素。
- **內容不跳位**：裁切、trim、改中心點時會自動補償 `x`／`y`；縮放以中心點為基準，`x`／`y` 不變。縮放面板的 % 以原圖為 100（`srcScale()`＝ops 裡所有 `xform` 的 `w/sw` 連乘，裁切不算），寬／高是目前的像素。

## 跟遊戲的對應

遊戲組零件在 `src/components/view.js` 的 `_addPart`（以及 `src/roles/dummy.js` 的 `ghost`）：

```js
sp.setScale(part.scale);
sp.setOrigin(part.ox ?? 0.5, part.oy ?? 1);
sp.x = part.x ?? 0;  sp.y = part.y ?? 0;  sp.angle = part.a ?? 0;
```

`x`／`y` 是零件中心點在角色 view 容器裡的位置。容器 (0,0) 是角色框（`w`×`h`）的中心；`anchor`（預設 0,16）是角色在地圖上的站立點，剛好是腳下那格 tile 的中心。「顯示 origin」勾選時，每個顯示中的圖層都畫出中心點十字（選取中＝黃、其他＝橘）。工具畫布上的參考線：紅十字＝(0,0)、白虛線＝角色框、藍框＋圓點＝anchor 那格 tile，數值可在上方調整。參考框的數字是「顯示單位」：沒勾 scale 時是圖片像素，勾了是遊戲像素，所以 tile 在畫面上的大小不隨勾選改變，變的是圖層。

## 檔案

- 開檔：工作資料夾固定是專案的 `images/`（殼選了專案資料夾就自動設好），從左側清單點 PNG；或從檔案總管拖 PNG（可連同名 `.json`）進畫布。有同名 `.json` 就套用裡面的擺放。
- 存檔：每層各自存，內建對話框只能存在工作資料夾底下，預設目錄是工作資料夾的 `output/`（沒有就用圖層所在目錄）、預設檔名 `原檔名-copy`，同名會問是否覆蓋；同時寫 PNG 和 `.json`。存檔不會自動 trim（以前的「存檔時自動 trim」拿掉了，舊專案的 `settings.autoTrim` 直接忽略），要裁就先按「裁到剛好」。
- **存到遊戲資料**（item.json／role.json）：兩個都是手寫的來源檔（`xls/item.xlsx`、`xls/role.xlsx` 已不同步），擺放由工具直接寫進去。存檔對話框的「存到遊戲資料」勾選：
  - 兩個資料夾都從殼給的專案根目錄推出來：工作資料夾＝`images/`（開圖、存專案、一般存檔），遊戲資料＝`public/assets`（要有 `json/item.json` 和 `roles_64x64/`，不對就在狀態列提示；`json/role.json` 有就一起配）。寫了 `item.json`／`role.json` 會廣播給其他分頁（見 [tools-shell.md](tools-shell.md)）。
  - 檔名（不含副檔名）等於某些 item 的 `equip.sprite`、或某些角色的 `body`／`head`／`hand`／`corpse` 的 `sprite`（`targetsOf()`）才能勾，預設勾、檔名預設就是圖層名；配不到或還沒選專案資料夾就反灰，hover 看原因。配到好幾個（共用 sprite，例如 `hand-man`）時列出 `id.欄位`（`h1.equip`、`wick.hand`）各自勾，hover 看是哪個檔。spritesheet 的 sprite（`weapons:3`、`animals:42`）配不到，武器、動物不走這條。
  - 勾了：PNG 覆蓋 `roles_64x64/<sprite>.png`（不看對話框選的目錄、不問覆蓋、**不寫 sidecar**），重新讀一次 json，勾選的那些物件寫入 `scale`／`x`／`y`，`a`／`ox`／`oy` 是預設值（0／0.5／1）就刪掉那個 key、否則寫入，其他 key（`sprite`、`aim`、`swing`、`ext`…）跟 `drop` 不動，有改到的檔才整份 `JSON.stringify(…, null, 2)` 重寫。存在工作資料夾外面，所以不會「改以剛存的檔當原圖」，原圖跟步驟留在專案裡。
  - 道具編輯器、角色編輯器開著也沒關係，它們存檔前會偵測到這裡寫過並三方合併。
  - 沒勾：照一般存檔（PNG＋sidecar）。
  - 新的 sprite 名稱還要手動在 `src/scenes/Preloader.js` 加 `this.load.image(...)`，遊戲才載得到。
- 不透明度：平常只影響顯示（存在專案裡，不進 `.json`）。圖層不透明度 < 100% 時，存檔對話框多一個「烘入不透明度」勾選（預設勾），勾了 PNG 的 alpha 會乘上它。存檔觸發「改以剛存的檔當原圖」且有烘入時，opacity 會歸 1（不然會乘兩次）。匯出 icon 時只要有顯示中的半透明圖層也會出現同一個勾選。
- `.json`（sidecar，給人看的，遊戲不讀）：

  ```json
  { "x": -3, "y": 6.75, "a": 30, "scale": 0.25, "ox": 0.5, "oy": 1,
    "xlsx": "\"sprite\":\"foo\",\"scale\":0.25,\"x\":-3,\"y\":6.75,\"a\":30" }
  ```

  `xlsx` 是可直接貼進 xlsx 儲存格的字串（不含大括號，`a`／`ox`／`oy` 是預設值時省略）。
- trim 門檻（工具區「門檻」欄，預設 16）：alpha 低於門檻的像素不算內容，「裁到剛好」、自動模式分塊、匯出 icon 共用。AI 圖外圍常散著 alpha 個位數的雜訊，門檻設 1 會被它們卡住裁不進去；門檻只影響邊界計算，範圍內的淡像素不會被清掉（要清用「清除透明」）。
- 專案（`*.pdproj.json`）：記每層的原圖路徑（相對工作資料夾，`src`）＋原圖尺寸、步驟清單 `ops`、擺放、顯示／鎖定／不透明度、圖層順序，以及上方的設定；undo 紀錄不存。
  - 開啟：左側清單點 `.pdproj.json`。畫布空的就直接開；已有圖層時問「加入／取代／取消」。取代＝清掉目前圖層、套用專案設定、清空 undo（有未存修改會先問）；加入＝疊在最上面、保留原座標、不重新置中、設定沿用目前的（scale 不同會 alert 警告），可以 undo（結構快照）；同一個專案（路徑相同）已經開著就不能再加入。
  - 圖層歸屬：每層的 `proj`（`{dir, path, name}`）**只在開專案時設定**，存專案永遠不改。複製／裁切到新圖層沿用來源層、合併沿用最底層、點 PNG／拖進來的沿用選取圖層（沒選取就是無）。畫布上有哪些專案是從圖層的 `proj` 算出來的。
  - 存專案：只存圖層清單最左邊 💾 打勾的圖層（`save`，預設勾、不進專案檔；hover 顯示所屬專案；全沒勾時按鈕停用），沒有 Ctrl+S。預設檔名：畫布上剛好一個專案＝它，否則 `project`；可以選工作資料夾裡任何專案覆蓋，覆蓋時如果 💾 的圖層跟那個專案的圖層（`proj` 指向它的那些）不是同一組，確認視窗多一行提示。
  - 標題（工具列小字與分頁標題）列出畫布上的專案（`body + sword`）；`*` 是整個畫布跟上次開／存時比對出來的，存到哪個專案都會清掉。加入專案時，原本沒有未存修改才會重設比對基準。
  - 拖進來的圖沒有原圖路徑，存專案前要先「存檔…」存進工作資料夾。圖層存檔時如果原本沒有原圖路徑、或覆蓋了自己的原圖，會改以剛存的檔當原圖、步驟歸零、清掉這層的 undo（不然步驟會被套用兩次）。
  - 開專案時原圖找不到就略過該層並警告；原圖尺寸跟存檔時不同也會警告（步驟是照舊尺寸記的，結果可能不對）。覆蓋原圖會影響引用它的其他專案。
- 匯出 icon：把顯示中的圖層壓平（位置、旋轉都烘進去），裁到不透明範圍、等比縮放置中到 N×N，只存 PNG。

## 程式結構

| 檔案 | 內容 |
|---|---|
| `main.js` | 狀態、繪製、滑鼠鍵盤、模式（移動／裁切／縮放／清除透明／顏色／移除綠色／變形／自動／像素）、UI 同步、開存檔 |
| `pixels.js` | 純像素運算：xform（平滑模式先每次縮一半到兩倍以內）、compose、warp、replay、erase、mask、alphaClear、fill、key、removeGreen、paint、opaqueBounds、blobs（連通塊）；工具建的 canvas 都是 `willReadFrequently`（getImageData 快很多） |
| `history.js` | 全域 undo／redo（快照 x/y/a/ox/oy/ops/canvas 參照；合併用的圖層清單結構快照） |
| `../common/fs.js` | 列目錄、讀寫檔；跟道具編輯器共用 |
| `../common/shell.js` | 跟殼的接線：收專案資料夾、寫 json 後廣播、回報未存狀態 |

`item.json` 的其他欄位用道具編輯器改（[item-editor.md](item-editor.md)）；兩邊同時開著也沒關係，道具編輯器存檔前會偵測紙娃娃寫過的 `equip` 並合併。

測試：`node scripts/test/paperdoll.mjs`（透過 `window.__pd` 驗證位置補償、undo、清除、填色／去色／滴管、多邊形裁切（含派 pointer 事件測互動）、變形、像素修補（畫／擦／模式內 undo／接著編輯／擋縮放／清除）、合併、sidecar、icon；專案存讀、存到 item.json 用 OPFS 當工作資料夾和假的 `public/assets`，因為無頭 Chrome 開不了資料夾選擇視窗）。
