# 部位（tools/part）

`part.json`（部位 pool）的總覽與整理：一次看到全部條目、誰在用、哪些壞了，做改名／改 kind／換圖／新增／複製／刪除。開法：`npm run dev` 後開 `/tools/` 的「部位」分頁（殼見 [tools-shell.md](tools-shell.md)）。

**不調擺放**：`scale/x/y/a/ox/oy/f` 在這裡唯讀，要調按「↗ 到試穿調」（見 [fit-tool.md](fit-tool.md)）；從圖產生新條目走紙娃娃「存到 pool…」（見 [paperdoll-tool.md](paperdoll-tool.md)）。

## 畫面

三欄，沒有 header（這頁沒有存檔／undo）：

- **左欄**（`splitter.js` 可拖寬度，記在 `tools.left.part`）：
  - 上面：搜尋（id 或 sprite）、篩選 全部／未使用／壞的（附數量）。篩選跟搜尋同時套在樹和縮圖總覽。
  - 樹：照 `ROLE_PARTS` 的順序分組（身體／鞋子／衣服／頭／頭髮／手），kind 不認識的另一組「不認識的 kind」。收合用 `fold.js`（預設全摺、Alt＋點全部、記在 `tools.part.open`、搜尋中全開），規則同道具編輯器：摺起選到的那組就取消選取，從別處選到（總覽卡片、新增、改名、↗ 跳過來）就展開那組。每列 20px 圖示＋id＋使用次數（hover 看是誰），沒人用的整列變灰，壞的加 ⚠（hover 看原因）。再點一次選到的列＝取消選取。
  - 下面：「＋ 新增」、狀態文字。
- **中間**：
  - 沒選＝**縮圖總覽**：上方一排部位分頁 `全部｜身體｜鞋子｜衣服｜頭｜頭髮｜手｜不認識的 kind`（附篩選／搜尋後的數量，0 的不列，但目前分頁空了也留著；記在 `localStorage` 的 `tools.part.tab`）；「全部」照同樣的組分段（有分段標題），其他一次只列一個部位，卡片畫原圖（不套 scale/x/y，等比縮進 64×64）＋id，右上是在用的角色數，沒人用標灰、壞的紅框；點卡片＝選取。
  - 選了＝**詳細**：標題列（大 id、kind、動作：↗ 到試穿調、改名…、改 kind…、換圖…、複製…、刪除…）、問題清單、原圖（160px）、欄位（唯讀，`kind` 以外全列，物件印 JSON）、使用者（每個角色一列＋↗ 跳角色分頁）。
- **右欄**（固定寬度，沒選時藏起來）：**套在人偶上的合成**，最下面 `男｜女` 切換（記在 `localStorage` 的 `tools.part.sex`，換條目保留）。只有畫布那層（`preview.js` 包的 `.cvbox`）會捲，預覽的選項列跟男女固定在右欄下方，放大到 ×6 也點得到；右欄最寬 50vw。重用角色編輯器的 `preview.js`，人偶＝人形範本尺寸（32×64、錨點 y 16）＋`body-man`／`body-woman`，條目自己是 body 就換掉身體；女＝`sex: 'f'`，照遊戲 `partFor()` 有 `f` 就套（標「用女版 f」），沒有就用基準數字（標「沒有 f，用基準數字」）。用來一眼看出擺歪，歪了去試穿修。底色可換（見下）。
- **未使用**：沒有角色的部位欄位指到它。只標示，不擋任何操作、沒有一鍵清除——路人隨機長相做出來之後，沒有角色在用不代表沒用。
- **壞的**（`problems()`）：sprite 在 textures.json 找不到（含格子編號超出範圍，`IC.check()`）、kind 不是六種之一、**放錯欄位**（有角色的 `hair` 指到 kind 是 `head` 的條目之類）。角色指到不存在的部位 id 是角色編輯器的檢查，這裡不重複。
- **合成底色**：`preview.js` 的選項列有顏色選擇器＋「棋盤格」（同試穿的 UI），選了純色就不畫棋盤格；同頁所有預覽一起換，記在 `localStorage` 的 `tools.preview.bg`（跟試穿的 `tools.fit.bg` 分開記）。角色編輯器的預覽也有。

## 動作（立刻寫檔＋廣播，沒有 undo）

每個動作都直接寫 `part.json`（`notifySaved`），危險的先確認。別的分頁存了 `part.json`／`role.json` 這裡就重讀（這頁沒有未存狀態）。

- **改名**：共用 `tools/common/part.js` 的 `askRename()`／`rename()`（角色編輯器的選圖器右鍵也是同一份）。新 id 只能英數字／底線／減號、不能撞名；第二個確認框列出要一起改的角色，以及 `src/`、`tools/`、`scripts/` 裡寫死這個 id 的行（只列不改，例如角色範本的 `body-man`；要有專案根目錄才掃）。`part.json` 換 key（位置不變），再讀 `role.json` 把部位欄位的引用換掉直接寫檔。
  - 改名前先廣播 `partRenamed`（`shell.js` 的 `notifyPartRenamed()`）：**角色分頁、試穿分頁有未存修改的話，先在記憶體跟著改**（角色分頁改引用；試穿改 `part.json` 的 key 跟 `role.json` 引用），之後它們存檔做角色／條目層級三方合併時，兩邊都改過的那筆以自己的為準，而自己的已經是新 id，所以不會被舊 id 蓋回去、也不會讓舊 key 復活。沒有未存修改的分頁照常因為存檔通知重讀。
- **改 kind**：有角色在用就擋（列出是誰），不然選一個 kind 寫回。改 kind 跟刪除只處理改名這種跨檔情況，其他分頁未存的同一條目修改，存檔合併時會照一般規則以那邊為準。
- **換圖**：icon 選圖器（`IC.pickIcon()`，可選 `sheet:格子`／`atlas:frame`）改 `sprite`，擺放不動。
- **新增**：對話框填 id、kind、圖（選圖器）；選圖時 id 還沒手動改過就自動帶 `sprite`（`:` 換成 `-`，撞名接 `-2`…）。數字抄同 kind 第一筆條目的 `scale/x/y`（沒有就不寫），排在同 kind 最後一筆後面，建好選到它。給怪物／動物這種 sheet 格子當身體的條目用（紙娃娃只會產生 `roles/parts/<id>.png`）。
- **複製**：同一個對話框，預設 id `<原 id>-2`、kind／圖帶原本的，整筆照抄（含 `f`），排在原本後面（kind 改了就排到那個 kind 最後）。
- **刪除**：有角色在用就擋；PNG 不刪（到「圖片」分頁搬到 .tbd）。
- **↗ 到試穿調**：找第一個用到它的紙娃娃型角色（有 `head` 或 `hand`，試穿只列這種），`gotoTab('fit', [角色, kind])`；試穿選那個角色、切到擺放分頁、游標放在那個部位的第一個數字欄。沒有紙娃娃型角色在用就停用。

測試：`node scripts/test/part-tool.mjs`（OPFS 當假的專案：分段、卡片標示、三種壞、篩選／搜尋、總覽部位分頁（只列一個部位、記住、跟篩選一起算數量、空了留著）、左樹分組／拖寬把手／點卡片展開並選取／列標示／再點取消／摺起取消選取、詳細合成、男女切換（套 body-woman、有無 f 的標示、記住）、到試穿停用、合成底色（記住、棋盤格恢復）、改 kind 擋／改、換圖、新增帶 id／抄數字／排序、複製、不合法 id、改名連帶 role.json、刪除擋／刪；殼裡：角色分頁跟試穿分頁有未存修改時被改名、記憶體跟著改、存檔合併結果正確，↗ 到試穿選角色並聚焦數字欄）。

不做的：調擺放數字（試穿）、從圖產生條目（紙娃娃）、刪 PNG（圖片分頁）、undo、一鍵清未使用、路人隨機長相的標籤／分組（之後的題目）。
